# WIN5特化サイト 実現可能性メモ

## 1. 結論

**「R9〜11に絞った分析・予想サイト」は現行パイプラインの延長で作れる。**
一方で **「WIN5のオッズ（＝口数の偏り）を分析する」部分は、DB側にデータが
入っているかの確認が先** で、そこが未確認のまま設計を進めても手戻りになる。

- 予想・確率の生成: **追加学習なしで即可能**。R9〜11は全レース分の確率を
  すでに毎日出しており、抽出して並べ替えるだけ。
- 的中シミュレーション（何点買えば何%当たるか）: **即可能**。本メモ §3 は
  公開済みHTMLに埋まっている確率だけで実際に計算した。
- WIN5の配当・的中票数・キャリーオーバーの分析: **DBに重勝式レコードが
  蓄積されているかに依存**（§2）。無ければ取込設定の変更 → 以後蓄積、
  過去分は再取得が必要。
- 「買えば勝てる」サイト: **現時点の検証結果からは推奨できない**。
  単勝市場に対する優位が確認できていない（ll_model 2.218 > ll_market 2.041）
  以上、WIN5でも期待値の源泉は確率精度ではなく**口数の偏り**側にしかない。

## 2. 先に確認すべきデータ（ecore.db 側・PCでしか叩けない）

スキーマは決め打ちしない。EveryDB3 のバージョン・取込設定でテーブル名が
変わるため、以下を実行して実物を見るところから始める。

```bash
# 1) 重勝式(WIN5)テーブルの有無を名前で探す
sqlite3 "%LOCALAPPDATA%\EveryDB3\ecore.db" ".tables"
# 2) 候補が見つかったら中身を確認（例: N_WIN5 / N_JYUSYO / N_WF 等、名称は要実確認）
sqlite3 ... "PRAGMA table_info(<候補テーブル>);"
sqlite3 ... "SELECT * FROM <候補テーブル> ORDER BY 1 DESC LIMIT 3;"
# 3) 単勝の票数（人気の偏りの代理変数）が入っているか
sqlite3 ... ".tables" | grep -i -E "hyo|hyosu|h1"
# 4) 期間と行数（WIN5は2011年4月開始・原則日曜のみ）
sqlite3 ... "SELECT COUNT(*), MIN(<日付列>), MAX(<日付列>) FROM <候補テーブル>;"
```

必要データと用途:

| データ | 用途 | 無い場合の代替 |
|---|---|---|
| 重勝式の払戻金・的中票数・発売票数 | 配当分析・バックテストの正解 | JRA公式サイトの公表値を手入力で蓄積（過去分は手間大） |
| 対象5レースの指定 | 当日の脚立て | JRA公表（前日確定）を毎週手入力でも運用可 |
| キャリーオーバー額 | 期待値の上振れ判定 | 同上 |
| 単勝票数（H1系） | 「人気の偏り」の推定＝勝ち筋の核 | 単勝オッズから逆算（控除率補正）。精度は落ちるが可 |
| 時系列オッズ | 既に有効（運用ステータスで確認済み） | — |

### 対象レースの定義（前提の訂正）

WIN5の対象5レースは**レース番号ではなく発走時刻で決まる**。JRAの説明では
「発走時刻が最も遅い各競馬場のメインレースを5レース目とし、そこから遡って
5レース」を指定する。したがって実際の対象は各場の10R〜12R付近に散らばり、
**「R9〜11」は近似でしかない**。サイトでは JRA が指定した5レースを
そのまま読む（DBの重勝式レコード、または毎週の手入力）必要がある。

なお 2026年4月に「土曜日発売の通年化」の告知が出ており、開催回数が従来の
日曜中心から増えている可能性がある（サンプル数の見積もりに効くので要確認）。

**重勝式のオッズは発売中に公開されない**（単勝のような時々刻々の配当表示が
ない）。したがって「WIN5のオッズ分析」は、厳密には
**事後の的中票数・配当から人気構造を推定する**か、
**単勝票数から5レース分の口数分布を近似する**かのどちらかになる。
この点は設計の前提として動かせない。

## 3. 公開済みの確率から計算した実現可能性（実測）

`race_2026*.html` に埋まっている確率（13開催日）を使い、各日の R9・R10・R11
（2〜3場）から5レースを選ぶ全組み合わせについて（実際の対象レースの代理）、確率の高い順に買ったときの
的中確率を計算した。市場込みAI予測（現行の掲出値、w=0.05）ベース。

| 買い点数 | 投資額 | 的中確率（平均） | 損益分岐に必要な配当 |
|---|---|---|---|
| 1点 | 100円 | 0.125% | 8.0万円 |
| 100点 | 1万円 | 4.5% | 22.2万円 |
| 1000点 | 10万円 | 16.9% | 59.2万円 |
| 5000点 | 50万円 | 35.9% | 139万円 |

補助的な観測:

- **R9〜11は前半より難しい。** 本命（1位）の勝率想定は R9〜11 が平均 26.2%、
  R1〜8 が 31.2%。クラスが上がり実力が接近するため、5レース全部当てる前提の
  WIN5は構造的に不利な側のレースを踏まされる。
- 日によるブレが大きい（1点的中率は 0.027%〜0.34% と10倍以上の開き）。
  「今週は買う / 見送る」の判断材料になるのはここ。
- 上の表の「必要配当」は、**人気順に買った買い目で実際に出る配当**と比べる
  必要がある。高確率の組み合わせ＝人気の組み合わせなので、配当は平均を
  大きく下回るのが普通。**この突き合わせができるまで、収支の話は結論が出ない**
  （＝§2の重勝式データが要る、という話に戻る）。

## 4. どこに勝ち筋があるか

WIN5はパリミュチュエル（控除率30%）で、配当は
`発売票数 × 0.7 ÷ 的中票数` で決まる。したがって期待値は

```
EV(組み合わせ) = p(model) × 発売票数 × 0.7 ÷ 的中票数(予想)
```

分子の `p` を上げる（＝予想精度）より、**分母の「その組み合わせを買っている
人の少なさ」を突く**方が勝ち筋として現実的。現行モデルは単勝市場に勝てて
いないが、WIN5の口数分布は**単勝人気の単純な掛け算より偏っている**（人気馬
同士の組み合わせに資金が集中する）ことが知られており、そこは確率精度とは
別の歪み。検証可能な仮説として:

- H1: 的中票数は「5レースの単勝票数シェアの積」より、人気サイドで過大。
- H2: 1レースでも人気薄が来た回の配当は、H1の歪みの分だけ理論値より高い。

H1/H2は重勝式データがあれば**過去データだけで検証できる**（予想モデルの
良し悪しと独立に検証できるのが利点）。ここが本サイトの固有価値になり得る。

## 5. R9〜11特化でできる分析メニュー（データ追加なしで可能）

1. **後半3Rだけのキャリブレーション実測**（現在の答え合わせは全レース混在）。
   R9〜11に限った本命勝率・確率帯別の実勝率・log loss。
2. **波乱度スコア**: レース内確率分布のエントロピー、本命の確率水準、頭数、
   クラス、距離。「今週のWIN5は堅い/荒れる」の事前指標。
3. **脚質・展開データの活用**: `pos`（想定位置取り）と `pace` は既に生成済み。
   後半レースだけの「逃げ・先行有利度 × 該当馬」の一覧。
4. **1点的中率・必要点数の自動計算**（§3の計算をそのままページ化）。
5. **見送り判定**: 上位人気の信頼度が低い日／必要配当が現実的でない日を明示。

## 6. サイト構成案（既存の静的公開の枠内）

現行は `run_day.py` がHTMLを生成して GitHub Pages に push する構成。
サーバは不要で、WIN5ページも同じやり方で足せる。

```
win5_YYYYMMDD.html   対象5レース・確率・買い目シミュレータ（JSに5脚分の確率を埋め込み、
                     点数スライダーで的中確率とカバー範囲をブラウザ側で再計算）
win5_summary.html    WIN5限定の答え合わせ（何点なら当たっていたか・想定配当との比較）
index.html           入口に「WIN5」タブを追加
```

ポイント: 組み合わせを全部書き出すとページが巨大になるため、**5レース分の
確率だけ配って、上位N点の列挙と的中確率はブラウザ側で計算**する
（ヒープで上位N件を取るだけなので数千点でも一瞬）。

## 7. 検証計画（買いルールは事前に固定する）

1. 対象: 重勝式データが揃った全期間のWIN5開催日。
2. ルール例（実装前に文章で固定）: 「市場込み確率の上位から累積カバー率
   X% に達するまで買う。ただし必要配当が過去同型の配当中央値を超える日は
   見送り」。
3. 集計: 的中回数・回収率・最大ドローダウン・見送り率を併記。
4. WIN5は2011年4月24日開始で、開催回数は年およそ50〜100回規模（土曜通年化の
   影響は要確認）。いずれにせよ **サンプルが致命的に少ない**ので、
   信頼区間を必ず付け、回収率が100%を超えても「有意ではない」と明記する。
5. モデル選択に回収率を使わない（精度指標は log loss / ECE のまま）。

## 8. 掲載範囲の注意

現行サイトは「オッズ・確定成績等の JRA-VAN データは掲載していません」と
明記して運用している。WIN5の配当・的中票数・票数は**JRA-VAN由来の原データ**
なので、同じ線引きを維持するなら:

- 掲載可: 自前で計算した確率・的中確率・必要点数・自分の予想の答え合わせ。
- 掲載不可（現行方針では）: 配当額・票数そのものの転記や一覧。
- 配当の実額に触れたい場合は JRA公式の公表ページへのリンクに留めるか、
  ローカル専用ページにして公開しない。
