## 2. 既存データの形（フェーズ1はこれだけで足りる）

`race_YYYYMMDD.html` の中に埋め込みJSONがある:

```html
<script type='application/json' id='race-data'>{...}</script>
```

構造:

```
meta: {date, learned, generated, blend}   # blend = w（現行 "0.05"）
romaji: {場コード: ローマ字}               # URLハッシュ用
tkmapnote: 展開図の注記
races: [
  {
    v: "中山", r: 11, code: "06", g: "芝2200m",
    h: [ [馬番, 馬名, AI予測%, 市場込みAI予測%, 差pt, 枠, [[tag種別, ラベル], ...]], ... ],
    pos:  [[馬番, 枠, スタート後, 3コーナー, 4コーナー], ...],   # 0〜1の想定位置
    pace: "スロー|ミドル|ハイ",
    tk:   展開の短評（文字列）,
    pt:   箇条書きコメント（配列）,
    dah:  データ分析の <details> HTML（そのまま埋め込まれている）,
    rel:  {lv: "high|mid|low", ja, tx}   # 予想の信頼度
  }, ...
]
```

**列の意味を取り違えないこと**（描画JSのヘッダ `'AI予測 ▮  市場込みAI予測 ▏  市場との差'` が正）:

- `h[2]` = **AI予測**（モデル単独）
- `h[3]` = **市場込みAI予測**（w=0.05 でブレンド。中身の大半は市場＝実質の市場確率）
- `h[4]` = `h[2] - h[3]`（差 pt）
- `h[3]` が `null` の日がある（オッズを記録できなかったレース）。**必ず None 判定を入れる**。

確率は%で、レース内で合計100%になるとは限らない → 使う前に正規化する。

## 3. 前チャットで確定している事実（再調査不要）

### モデルの立ち位置（`summary.html` より）

- 累積 271R。log loss: **ll_model 2.21795 / ll_market 2.04087 / ll_final 2.04150**
  → **モデル単独は市場に負けている。ブレンド後も市場と同等（わずかに悪い）**。
- 本命の勝率: AI予測 26.6% / 市場込み 34.2% / 1番人気 34.6%。
- キャリブレーションは良好（ECE 0.0095、標本ノイズの範囲内＝「較正ずれの証拠なし」）。
- **結論: 確率精度を源泉にした期待値プラスは主張できない。**

### 公開済み確率から実測したWIN5の数字（13開催日・市場込み確率ベース）

R9〜11から5レース選ぶ全組み合わせ、確率上位から買った場合:

| 買い点数 | 投資額 | 的中確率 | 損益分岐に必要な配当 |
|---|---|---|---|
| 1点 | 100円 | 0.125% | 8.0万円 |
| 100点 | 1万円 | 4.5% | 22.2万円 |
| 1000点 | 10万円 | 16.9% | 59.2万円 |
| 5000点 | 50万円 | 35.9% | 139万円 |

- 本命の勝率想定: R9〜11 = 26.2% / R1〜8 = 31.2%（**後半のほうが難しい**）。
- 日ごとのブレが大きい（1点的中率 0.027%〜0.34%）。見送り判断の材料はここ。

### WIN5のルール（確認済み）

- 対象5レースは**レース番号ではなく発走時刻**で決まる。発走時刻が最も遅い
  各場メインを5レース目とし、そこから遡って5つ。**「R9〜11」は近似**。
- 控除率30%（払戻率70%）。2011-04-24開始。2026年4月に「土曜発売の通年化」告知あり。
- 発売中に重勝式のオッズは公開されない（＝事前に組み合わせ別EVは直接計算できない）。

### 未確認（PCでしか確認できない）

## 4. フェーズ1の実装仕様（次のセッションがやること）

### 出力

`win5_YYYYMMDD.html` — 既存ページと同じ静的HTML、同じ配色・フォント体系
（`race_20260913.html` の `<style>` を踏襲）。

### 中身

1. **対象5レース**: JRAが指定した5レースを扱う。当面は
   「その日の R9〜11 から選ぶ」ではなく、**設定ファイル/引数で5レースを渡す**形にする
   （例: `--legs 中山10,中山11,阪神10,阪神11,阪神12`）。指定が無い日は
   発走時刻の代理として後半レースから自動推定し、**推定である旨をページに明示**する。
2. **各脚の確率表**: 既存の行UI（枠/馬番/馬名/AI予測/市場込み/差）を流用。
3. **買い目シミュレータ**: 5脚分の確率だけをJSONで埋め込み、
   **上位N点の列挙と累積的中確率はブラウザ側で計算**する。
   - 全組み合わせを書き出さない（14^5 ≈ 54万点。ページが破裂する）。
   - アルゴリズム: 各脚を確率降順にソート → ヒープで積の大きい順に上位N件を取り出す
     （§5の Python 実装がそのまま JS に移せる）。
   - UI: 点数スライダー（1〜5000）→ 投資額・累積的中確率・損益分岐に必要な配当を表示。
   - 「軸1頭」「N頭流し」の切り替えもこの仕組みでそのまま出せる。
4. **波乱度**: 各脚の本命確率・エントロピー・頭数を出し、
   「今日は堅い/荒れる」を数値で示す。過去日との比較（当日を含む直近N日の分布）。
5. **見送り表示**: 必要配当が非現実的な日は明示する。憲法4・5（下記）に沿って、
   **買いの推奨はしない**。研究用の但し書きは既存ページの文言を流用する。

### やらないこと（フェーズ1では）

- 配当・票数の掲載（§6の規約）。
- モデルの再学習・特徴量追加。
- 実オッズのスクレイプ。

## 5. 計算の参照実装（前チャットで実際に使ったもの）

`.gitignore` で `*.py` が除外されているためコードとして置けない。そのまま貼って使う。

```python
import re, json, glob, heapq, itertools, statistics, math

def load(f):
    h = open(f, encoding='utf-8').read()
    m = re.search(r"id='race-data'>(.*?)</script>", h, re.S)
    return json.loads(m.group(1)) if m else None

def probs(rc, idx):           # idx=2: AI単独 / idx=3: 市場込み
    v = [x[idx] for x in rc['h']]
    if any(p is None for p in v):
        return None           # オッズ未記録の日
    v = [max(p, 0.01) for p in v]
    s = sum(v)
    return sorted([p / s for p in v], reverse=True)

def coverage(legs, budget):   # legs: 5脚分の降順確率リスト
    n = len(legs)
    start = tuple([0] * n)
    seen = {start}
    h = [(-math.prod(l[0] for l in legs), start)]
    tot, cnt, out = 0.0, 0, {}
    mx, marks = max(budget), set(budget)
    while h and cnt < mx:
        negp, idx = heapq.heappop(h)
        tot += -negp
        cnt += 1
        if cnt in marks:
            out[cnt] = tot    # 上位cnt点を買ったときの累積的中確率
        for i in range(n):
            if idx[i] + 1 < len(legs[i]):
                nx = list(idx); nx[i] += 1; nx = tuple(nx)
                if nx not in seen:
                    seen.add(nx)
                    heapq.heappush(h, (-math.prod(legs[j][nx[j]] for j in range(n)), nx))
    return out
```

§3の表は、各日の R9〜11（2〜3場）から5レース選ぶ全組み合わせ
`itertools.combinations(late, 5)` について上を回し、平均したもの。
損益分岐配当 = 投資額 ÷ 的中確率。

## 6. 守るべき制約

### 掲載範囲（既存サイトの方針）

全ページのフッタに「**オッズ・確定成績等の JRA-VAN データは掲載していません**」と
明記して運用している。WIN5でもこの線を維持する:

- 掲載可: 自前計算の確率・的中確率・必要点数・自分の予想の答え合わせ。
- 掲載不可: 配当額・票数そのものの転記・一覧（JRA-VAN由来の原データ）。
- 実配当に触れるなら JRA公式へのリンク、またはローカル専用ページ（非公開）。

### 予想スキルの憲法（`keiba-prediction` スキル）

実装セッションでも同じ制約が効く:

1. 数値は必ず計算から出す（記憶で勝率・配当・回収率を書かない）。
2. 発走前に観測できない情報を使わない（確定オッズ・結果由来の集計はリーク）。
3. 買いルールは事前登録。結果を見て閾値を動かしたら「事後調整」と明記。
4. モデル選択に回収率を使わない（主指標は log loss と ECE）。
5. ステークはフラクショナルKelly上限。

### 表示上の但し書き

既存ページと同じく「研究用の参考表示です。買い目の推奨ではありません。」を入れる。
モデルが市場に勝てていない事実（§3）を隠す表示にしない。
